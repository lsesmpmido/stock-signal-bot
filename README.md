# stock-signal-bot

ニュースから注目銘柄を見つけて Discord に提案し、承認した銘柄の売買シグナルを 2 種類のチャート画像付きで通知する Bot。

- **ニュース**: Google News RSS から記事を集め、JPX 上場銘柄一覧と照合して銘柄を特定する。そのうえで Jev (TypeSafe AI) で、プラス材料か・影響の大きさ・材料の種類（業績／株主還元／提携・M&A／受注・契約／新製品・新事業／政策・市況／その他 の 7 種類）を判定する。材料の種類は提案に表示し、答え合わせで種類ごとの成績を集計する
- **関連銘柄**: プラス材料と判定された銘柄の取引先・提携先・親子会社なども、同じニュースで影響を受けるかを判定して提案する（関係データは [JP Market Vis](https://mattyamonaca.github.io/JP_Market_Vis/)）
- **仮想売買**: 軍資金 240 万円を新NISA（成長投資枠）と特定口座で運用する練習ができる。税金・手数料も計算する
- **シグナル**: 日足で判定する。RSI(14) が 30 以下 / 70 以上に入った、25 日線と 75 日線がクロスした、MACD(12,26,9) がシグナル線とクロスした、のいずれかで通知する（200 日線はチャート表示のみ）。状態が変わった瞬間だけ通知し、同じシグナルは 24 時間に 1 回まで。通知には「過去の似た局面」（この銘柄で直近 2 年に同じシグナルが出た回数と、その 5・20 営業日後の平均の騰落率・上がった回数）も載せる
- **必要なもの**: Python 3.10 以上、PostgreSQL、Discord Bot、Jev の API キー

## セットアップ

### 環境変数

`.env.example` をコピーして `.env` を作り、値を書く。`.env` は Git の管理対象外。

```bash
cp .env.example .env
```

| 環境変数 | 内容 |
|---|---|
| `DISCORD_TOKEN` | Discord Bot のトークン（手順 1-2） |
| `DISCORD_CHANNEL_PROPOSAL` | 新銘柄提案を投稿するチャンネルの ID（手順 1-4） |
| `DISCORD_CHANNEL_SIGNAL` | 売買シグナルを投稿するチャンネルの ID（手順 1-4） |
| `DISCORD_CHANNEL_REPORT` | 任意。定番レポートと、約定・AI の売買・AI の判断の通知を投稿するチャンネルの ID。未設定なら売買シグナル用のチャンネルに投稿する |
| `DISCORD_GUILD_ID` | 任意。サーバー ID を入れると、スラッシュコマンドがすぐに反映される |
| `JEV_API_KEY` | Jev の API キー（手順 3） |
| `DATABASE_URL` | PostgreSQL の接続文字列（手順 2） |
| `PORT` | 任意。Web サーバー（ヘルスチェックと Web の画面）のポート（既定 8080）。実行環境が自動で設定する場合はそれに従う |
| `DASHBOARD_URL` | 任意。Web のポートフォリオ画面の URL（例: `https://xxx.example.com`。実行環境の URL）。設定すると `/dashboard` でログイン用のリンクを出せる |
| `DASHBOARD_USER_ID` | 任意。Web の画面を見られる Discord のユーザー ID。未設定なら Bot の所有者（Developer Portal でアプリを作った人） |

### 1. Discord Bot

**1-1. アプリケーションを作る**
1. [Discord Developer Portal](https://discord.com/developers/applications) を開き、Discord アカウントでログインする
2. **New Application** を押し、名前を入れて作成する

**1-2. Bot のトークンを取る**
1. 左メニューの **Bot** を開く
2. **Reset Token** を押し、表示されたトークンを `DISCORD_TOKEN` に書く
   - トークンは一度しか表示されない。なくしたら Reset し直す
   - トークンは Bot のパスワードと同じ扱い。人目に触れる場所に置かない
3. **Public Bot** を OFF にする（他人がこの Bot を自分のサーバーに入れられないようにするため）
4. **Privileged Gateway Intents** はすべて OFF のままでよい

**1-3. サーバーに招待する**
1. 左メニューの **OAuth2** → **OAuth2 URL Generator** を開く
2. SCOPES で `bot` と `applications.commands` にチェックを入れる
3. BOT PERMISSIONS で次にチェックを入れる
   - View Channels
   - Send Messages
   - Embed Links
   - Attach Files
   - Read Message History
   - Create Public Threads（週末の振り返りスレッド用）
   - Send Messages in Threads（同上）
4. 生成された URL をブラウザで開き、招待先のサーバーを選ぶ

**1-4. チャンネルを用意して ID を控える**
1. 提案用とシグナル用のテキストチャンネルを作る（例: `#新銘柄提案`、`#売買シグナル`）
   - 非公開チャンネルにする場合は、チャンネルの権限に Bot を追加する
2. Discord の **ユーザー設定 → 詳細設定 → 開発者モード** を ON にする
3. 次の ID をコピーして `.env` に書く
   - 各チャンネルを右クリック →「チャンネル ID をコピー」
   - サーバーアイコンを右クリック →「サーバー ID をコピー」

`/settings`・`/watch`・`/alert`・`/buy`・`/sell`・`/portfolio`・`/orders`・`/battle`・`/deposit`・`/reset`・`/chart`・`/ranking`・`/compare`・`/related`・`/map`・`/sentiment`・`/review`・`/test` は、「サーバーの管理」権限を持つメンバーにだけ表示される。

- **実行時にも確認する**: 表示の設定はサーバー側で変えられるので、実行時にも Bot が権限を確かめ、権限のない人には断りのメッセージを返す
- **DM では使えない**: コマンドはサーバーの中でだけ使える
- **`DISCORD_GUILD_ID` を設定した場合**: そのサーバーでだけ使える
- **ボタンも同じ権限が必要**: 状態を変えるボタン（`➕ 監視対象に追加`・`❌ スキップ`・`🗑️ 監視解除`・`💰 仮想で買う`・整理タイム）も、同じ権限を持つメンバーだけが押せる
- **誰でも押せるボタン**: `🔍 なぜ動いた？` と銘柄当てクイズ

### 2. PostgreSQL

どの PostgreSQL でも使える（自前のサーバー、Docker、マネージドサービスなど）。空のデータベースを 1 つ用意し、接続文字列を `DATABASE_URL` に書く。

```
postgresql://user:password@host:5432/dbname
```

- テーブルは Bot の初回起動時に自動で作られる
- サーバーが SSL に対応していれば、SSL で接続する
- パスワードに `@` `:` `/` `#` `?` などの記号が含まれる場合は、URL エンコードする（例: `@` → `%40`）

Docker で手早く用意する例:
```bash
docker run -d --name stock-signal-db -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:16
# DATABASE_URL=postgresql://postgres:postgres@localhost:5432/postgres
```

### 3. Jev（TypeSafe AI）
1. [typesafe.ai](https://typesafe.ai/) でサインアップする
2. [console.typesafe.ai](https://console.typesafe.ai/) で API キーを発行し、`JEV_API_KEY` に書く

### 4. 起動する
```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

起動ログに次の 4 行が順に出れば成功:
```
ヘルスチェック用サーバーを起動しました (port 8080)
DB 初期化完了
JPX 銘柄一覧をダウンロードしてキャッシュしました (3712 件、上場廃止 0 件)
ログインしました: <Bot 名> (銘柄マスタ 3712 件)
```

2 回目以降の起動では、3 行目が `JPX 銘柄一覧を DB キャッシュから読み込みました (3712 件)` になる（一覧が 7 日より古いときだけ再ダウンロードする）。件数は時期によって変わる。

ログイン後に、関連銘柄用の関係データの読み込みログ（`関係データをダウンロードしてキャッシュしました` または `関係データを DB キャッシュから読み込みました`）も出る。

Discord での動作確認:
1. `/watch add <証券コード>` を実行し、「〇〇 (コード) を監視対象に追加しました」と出ることを確認する
2. `/watch list` で一覧に出ることを確認する
3. `/settings` でメニューが出ることを確認する

Jev の判定だけを試す:
```bash
.venv/bin/python jev_client.py "トヨタ自動車、通期業績予想を上方修正" "トヨタ自動車"
```

### 5. サーバーで常時動かす

常駐プロセスを動かせる環境ならどこでも動く。

- ビルド: `pip install -r requirements.txt`
- 起動: `python main.py`
- 環境変数: 上の表の値を実行環境に設定する
- メモリ: 512MB あれば足りる
- ヘルスチェック: `GET /health` が `ok` を返す（起動処理中は `starting`）。実行環境のヘルスチェック設定に使える（`/` は Web のポートフォリオ画面なので、ヘルスチェックには `/health` を指定する）

**同じトークンで Bot を 2 つ起動しないこと。** 手元とサーバーの両方で動かすと、通知が二重に届く。

### うまく動かないとき

| 症状 | 原因と対処 |
|---|---|
| スラッシュコマンドが出てこない | `DISCORD_GUILD_ID` を設定する。Discord を再読み込みする（`Ctrl+R`）。招待時に `applications.commands` にチェックを入れたか確認する |
| `/settings`・`/watch`・`/alert`・`/buy` などのコマンドだけ出ない | 「サーバーの管理」権限がない。サーバーのオーナーか管理者で試す |
| 起動直後に `環境変数が設定されていません: …` と出て止まる | 表示された環境変数が設定されていない。実行環境の環境変数を確認する（名前のつづりにも注意） |
| 起動時に DB 接続エラー | 接続文字列のホスト・ポート・パスワードを確認する。パスワードの記号が URL エンコードされているか確認する。実行環境から DB サーバーに接続できるか（ファイアウォールなど）確認する |
| 提案やシグナルが投稿されない（ログに `403 Forbidden` / `Missing Access`） | Bot がそのチャンネルを見られない。まず、サーバーのメンバー一覧に Bot がいるか確認する。いなければ、招待時に `bot` へのチェックが漏れている（`applications.commands` だけだと、コマンドは使えても投稿はできない）。手順 1-3 で招待し直す。メンバーにいる場合は、チャンネルの権限に Bot を追加し、チャンネル ID が正しいかも確認する |
| 通知が二重に来る | Bot が 2 つ動いている。片方を止める |
| しばらくすると Bot が反応しなくなる | プロセスが止まっている。実行環境のログを確認する |

## 使い方

| 操作 | 内容 |
|---|---|
| 提案メッセージの `➕ 監視対象に追加` / `❌ スキップ` | 提案された銘柄を監視対象にする / 見送る。スキップ後に理由（高すぎる・業種が苦手など）を選べる |
| `/watch add <証券コード>` | 銘柄を監視対象に追加する。JPX の一覧にまだ載っていない新規上場銘柄も、株価データで上場を確認できれば追加できる |
| `/watch remove <証券コード>` | 監視を解除する（入力中に、監視中の銘柄が候補に出る） |
| `/watch list [タグ]` | 監視中の銘柄を一覧表示する（⭐ が先頭。タグで絞り込める）。メニューから選んで解除もできる |
| `/watch memo <証券コード> [メモ]` | 「なぜ監視したか」のメモを残す（シグナル通知にも表示。空にすると削除） |
| `/watch star <証券コード>` | お気に入り（⭐）を付け外しする。⭐ の銘柄のシグナルは目立たせ、⭐ を付けた人にメンションする |
| `/watch tag <証券コード> <タグ>` | タグ（長期・短期・様子見・なし）を付ける |
| `/alert add <証券コード> <価格>` | 指定した価格を超えた（今より上なら）・割った（今より下なら）ときに通知する |
| `/alert list` / `/alert remove` | 設定中のアラートを表示する / 取り消す |
| シグナル通知の `🗑️ 監視解除` | その銘柄の監視を解除する |
| シグナル通知・大引けレポート・話題銘柄の急騰・急落の `🔍 なぜ動いた？` | その銘柄の直近 2 日のニュースを社名で検索し、押した人にだけ表示する。大引けレポートでは、監視・保有銘柄のうち今日 ±3% 以上動いた銘柄（最大 5 つ）に付く |
| `/settings` | 新銘柄提案（1日2回 / 1日1回 / OFF）と売買シグナル（15分 / 1時間 / 大引け後 / OFF）の頻度、定番レポートの ON/OFF を変更する |
| `/buy <証券コード> [金額(万円)]` | 仮想で買う（金額を省略すると 20 万円分）。提案やシグナル通知の `💰 仮想で買う` ボタンでも買える |
| `/sell <証券コード> [株数] [口座]` | 仮想で売る（株数を省略すると全部。口座を省略すると両方の口座から、特定口座を先に売り、足りない分を NISA から売る） |
| `/portfolio [チーム]` | 仮想ポートフォリオの保有・含み損益・通算成績・今年の NISA 枠の残りを表示する（チームに慎重AI・大胆AI を選ぶと、その AI の口座） |
| `/orders` | すぐ約定しなかった注文（取引時間外・昼休み・寄り付き直後に出したもの）を表示し、取り消す |
| `/battle` | AI との勝負の状況（3 チームの今月の途中経過・通算成績・慎重 AI の性格）を表示する |
| `/deposit <金額(万円)>` | 仮想口座に入金する（自分と 2 つの AI に同じ額。いつでも入金できる） |
| `/reset` | 現金・すでに持っている銘柄を指定して、3 チームの勝負を同じ条件でやり直す（「AI との勝負」の「初期条件の設定」） |
| `/chart <証券コード>` | チャート 2 枚（詳細テクニカル・マルチ時間軸）を表示する |
| `/ranking [期間]` | 監視銘柄と仮想保有銘柄の騰落ランキング（今日・1週間・1か月） |
| `/compare <証券コード> [証券コード] [期間]` | 2 銘柄の値動きを、期間の初日を 100 にそろえて重ねたチャートで比べる（3か月・6か月・1年・2年）。2 つ目を省略すると、その銘柄の業種の ETF（NEXT FUNDS TOPIX-17 業種別、1617〜1633）と比べる（同業他社との比較の代わり） |
| `/related <証券コード> [段階]` | 関係データから、その銘柄の関連企業（取引先・親子会社・提携先など）を影響の大きい順に表示する。段階に「2 段階」を選ぶと、関連企業の関連企業までたどった連想ツリーを表示する（1 段階目 8 社 × 各 3 社まで） |
| `/map` | 監視銘柄・保有銘柄（最大 10 社）と、それぞれ業績への影響が大きい関連企業（4 社まで）のつながりを図にする。線の太さは関係の強さ（主要取引先・親子会社が最も太い） |
| `/sentiment <証券コード>` | その銘柄のニュースの感情スコア（Jev の「プラス材料の確率」）の直近 90 日の推移を、株価と並べたグラフで表示する。記事ごとの点と日ごとの平均、最近の記事 5 件を載せる |
| `/review [期間]` | 過去の提案の答え合わせを表示する（期間は 1 週間〔5 営業日後〕か 1 か月〔20 営業日後〕） |
| `/dashboard [操作]` | Web のポートフォリオ画面を開くための、1 回限りのログイン用リンクを自分だけに表示する。操作に「すべての端末からログアウトする」を選ぶと、ログイン中の端末をすべてログアウトさせる（「Web のポートフォリオ画面」を参照） |
| `/test proposal` | 動作確認用。ニュース収集から提案の投稿まで（関連銘柄を含む）を今すぐ実行し、各段階の件数を表示する |
| `/test report <種類>` | 動作確認用。朝・大引け・週間のレポートを今すぐ送る（ON/OFF の設定に関係なく） |
| `/test signal <証券コード>` | 動作確認用。シグナルの有無に関係なく、指定した銘柄のチャート付き通知を送る（監視状態は変えない） |

`/chart`・`/ranking`・`/compare`・`/related`・`/map`・`/sentiment` は、オプションで「自分だけに表示」を選べる（既定はチャンネルの全員に表示）。

`<証券コード>` には東証の証券コードを入れる。4 桁の数字のほか、`130A` のような英数字のコードも使える（例: `/watch add 7203`）。

### 実行タイミング（日本時間）
- **新銘柄提案**: 1日2回なら 8:30 と 16:00、1日1回なら 8:30（土日も動く）。監視中の銘柄と、直近 3 日以内に提案した銘柄は提案しない。1 回の提案はニュースの銘柄が最大 10 件、関連銘柄が最大 5 件
  - 同じタイミングで、監視銘柄の直近 1 日のニュースを社名で検索し、まだ判定していない記事を Jev で判定して記録する（1 社 5 件・1 回 40 件まで。提案はしない）。Jev の判定は、提案しなかったものも含めてすべて `news_judgements` に残し、`/sentiment` で使う
- **売買シグナル**: 東証の取引日だけ動く（土日・祝日・12/31〜1/3 を除く）。データが約 20 分遅れるため、場中の時刻を後ろにずらしている
  - 15分間隔: 9:15〜11:45、12:45〜15:45 と 15:55
  - 1時間間隔: 10:00〜15:00 の毎正時と 15:55
  - 1日1回: 15:55（15:30 の終値が届いた後）
- **定番レポート**: 朝のブリーフィングは取引日の 8:45、大引けレポートは取引日の 16:05、週間レポートは週の最後の取引日（通常は金曜、祝日なら前の取引日）の 16:10、銘柄当てクイズは取引日の 12:00、週末の振り返りスレッドは土曜の 9:00、週末の整理タイムは土曜の 10:00
- **注文の約定・慎重 AI の損切り**: 取引日の 9:30・10:00・11:00・13:00（「仮想売買」「AI トレーダー」を参照）
- **大胆 AI の場中の判断**: 取引日の 10:00・11:00・13:00・14:00・15:00（「大胆 AI」を参照）
- **話題銘柄の急騰・急落**: 取引日の 10:00・11:00・13:00・14:00・15:00 に、直近 3 日に提案した銘柄（監視していないもの）の今日の値動きを調べ、前日の終値から ±7% 以上動いていれば提案用チャンネルに知らせる（1 銘柄 1 日 1 回まで。新銘柄提案が OFF なら動かない）
- **日足の保存**: 取引日の 16:00 に、監視銘柄・直近 35 日に提案した銘柄・自分と AI の仮想の保有銘柄・自分が直近 20 営業日に仮想で買った銘柄（AI の候補）・日経平均・TOPIX 連動 ETF（1306）の確定した日足を DB に保存する。続けて、3 チームの総資産の記録と、慎重 AI の判断・大胆 AI の大引け後の判断を行う
- **一覧データの更新**: JPX の上場銘柄一覧・関係データ（JP Market Vis）・決算日（EDINET コードリスト）は、それぞれ 7 日より古くなったら取り直す

### 調整できる設定
DB の `user_settings` テーブルを直接編集する。
- `jev_positive_threshold`（既定 0.7）: プラス材料の確率がこれ以上なら提案する
- `jev_impact_threshold`（既定 1.0）: インパクト（0〜2）がこれ以上なら提案する
- `watch_limit`（既定 10）: 監視できる銘柄数の上限
- `vp_fee_rate`（既定 0）: 仮想売買の手数料率（売買代金に対する割合。例: `0.0022` = 0.22%）
- `vp_default_amount`（既定 200000）: 仮想売買で金額を省略したときの購入額（円）
- `bold_jev_daily_limit`（既定 60）: 大胆 AI が 1 日に Jev を呼べる回数の上限

## 監視銘柄の管理
- **監視枠**: 監視できる銘柄は 10 銘柄まで（`watch_limit` で変更可）。満杯のときに追加しようとすると、入れ替える銘柄を選ぶメニューが出る（入れ替えないことも選べる）
- **週末の整理タイム**: 土曜 10:00 に、外す候補を最大 3 つ（😴 30 日以上シグナルなし・📉 監視開始から -10% 以上・🕰️ いちばん古い）提示する。「続ける」を選んだ銘柄は 4 週間は候補に出さない。`/settings` で ON/OFF できる
- **価格アラート**: 取引時間中に 15 分おきに、アラートを作った日以降の高値・安値で判定する。作った日は、作る前にすでに指定価格に達していたら判定に使わず、翌取引日から判定する（作る前の値動きで鳴らないようにするため）。達したら売買シグナル用チャンネルに 1 回だけ通知し、作った人にメンションする（株価は約 20 分遅れ）
- **スキップの理由**: 記録しておき、将来の判断基準の自動調整に使う

## 仮想売買
実際にお金を動かさずに、銘柄選びと売り時の判断を練習する機能。監視（通知）とは別の機能で、仮想で買っても監視対象には入らず、通知も増えない。

- **軍資金**: 240 万円（新NISA 成長投資枠の年間上限と同じ）。現金は 2 つの口座で共通。成績は入金額の合計に対する損益で計算する（軍資金をどれだけ増やせたか）
- **口座**:
  - **新NISA（成長投資枠）**: 先に使う。1 年間に買えるのは購入額の合計 240 万円まで。売っても同じ年の枠は戻らず、翌年 1 月に復活する。非課税
  - **特定口座**: NISA の枠を超える分はこちらで買う。売却益に 20.315% の税金がかかる。同じ年の損益は相殺し、損が出たら払い過ぎた税金を戻す
- **買い方**: 金額を指定し、その金額で買える株数を 1 株単位で買う。NISA の枠が一部しか残っていないときは、NISA と特定口座に分けて買う
- **売り方**: 株数を省略すると全部売る。口座を指定しなければ両方の口座が対象で、特定口座から先に売り、足りない分を NISA から売る（NISA は長く持つ前提のため）
- **約定のタイミング**: 取引時間中（前場 9:00〜11:30、後場 12:30〜15:30）は最新の株価（約 20 分遅れ）ですぐ約定する。それ以外は注文として受け付け、次の寄り付きの始値で約定する（見えている株価を見てから、その株価で売買できないようにするため）。未約定の注文は `/orders` で取り消せる。5 営業日たっても約定しない注文（売買停止など）は取り消す
  - 取引時間外（15:30〜翌朝 9:00）の注文: 翌取引日の始値（寄り付き前の注文は今日の始値）
  - 寄り付き直後で、今日の株価がまだ取れないときの注文: 今日の始値
  - 昼休みの注文: 今日の後場の始値（12:30）。株価が約 20 分遅れるので、後場の株価が届く 12:50 までは昼休みと同じ扱いにする
- **注文の約定**: 取引日の 9:30・10:00・11:00・13:00 に、未約定の注文を始値（昼休みの注文は 13:00 に後場の始値）で約定させ、結果をレポート用チャンネルに知らせる。約定の処理を始める前に注文を「約定中」にするので、取り消しと同時に約定することはない
- **手数料**: 既定は 0 円（主要ネット証券の国内株式の売買手数料は無料が主流のため）。`vp_fee_rate` で変更できる。特定口座では手数料を利益から差し引いてから税金を計算する
- **売却時の成績カード**: 保有期間、税金・手数料込みの損益、同じ期間の TOPIX（連動 ETF 1306）との比較、成績に応じた称号を表示する
- **株式分割・併合**: 日足の取り直しで分割を見つけたら、分割日より前からある保有の株数（取得額の合計は変えない）・未約定の売り注文の株数・価格アラートの価格を、分割に合わせて直す。直した内容は、16:00 の日足保存の後にレポート用チャンネルに知らせる。分割比は株価の変化から判定する（1:2・2:3・2:1 の併合などの比にならないときは直さず、ログに残す）。併合で出た端数の株は切り捨てる
- **省略していること**: NISA の生涯投資枠（成長投資枠 1,200 万円）、配当金

## AI トレーダー
AI（Jev）が、自分と同じルール（新NISA＋特定口座、軍資金・税金・手数料）の別口座で仮想売買する。性格の違う 2 つの AI（🤖 慎重AI・⚡ 大胆AI）が同時に動く。AI の口座は `/portfolio` でチームを選ぶと見られる。この節は慎重 AI の説明。大胆 AI は次の節を参照。

- **候補**: 直近 10 営業日以内の提案銘柄（承認・スキップに関係なく）、自分の監視銘柄、自分が仮想で買った銘柄（保有中と直近 20 営業日以内の購入）。AI がすでに持っている銘柄は除く
- **判断のタイミング**: 毎取引日の大引け後（16:00 の日足保存の直後）に判断して注文を出し、翌取引日の始値で約定する。提案された時点では候補に入るだけで、すぐには買わない。取引時間中に判断するのは損切りだけ
- **買う**: Jev に「翌取引日の寄り付きで買うべきか」を、ニュースの評価（プラス材料の確率・影響の大きさ・材料の種類）と値動きの状態（RSI・25 日線からの乖離・MACD・提案からの値動き）から判断させる。確信度がモードの基準以上なら買う（1 日 3 件まで）
- **高値づかみを防ぐ安全ルール**: 提案から 10% 以上上昇、RSI 70 以上、25 日線から 15% 以上の上方乖離のいずれかなら買わない
- **売る**: 損切り（-15%）、最長保有（120 営業日）、Jev の「売るべきか」の判断
- **取引時間中の損切り**: 9:30・10:00・11:00・13:00 に保有銘柄の株価（約 20 分遅れ）を確かめ、含み損が -15% に達していれば、その場の株価ですぐ売る（自分の取引時間中の売買と同じ条件）。Jev には聞かない。売った後にレポート用チャンネルに知らせる。前日の判断で出した売り注文がまだ約定していない銘柄は、その注文に任せる
- **入れ替え**: 現金が足りないときは、候補の確信度が、保有で最も見劣りする銘柄の「持ち続ける確信度」を 0.15 以上上回る場合だけ、売って買い替える
- **性格（モード）**: 月ごとの勝敗で変わる。資金は限られているので、1 回の金額が大きいほど保有銘柄は少なくなる
  - 🛡️ 堅実（AI が通算で勝ち越し）: 1 回 15 万円で分散。確信度の基準を厳しくし、+10% で利益確定
  - 😐 通常（互角）: 1 回 20 万円
  - 🥋 弟子（AI が 1〜2 か月連続で負け）: 自分が買ったときの状態（RSI・25 日線からの乖離）に近い候補を優先する。自分の売買をその場でコピーするのではなく、一歩遅れて追いかける
  - 🎲 勝負師（AI が 3 か月以上連続で負け）: 1 回 40 万円で少数に集中。確信度の基準と高値づかみ防止のルールを緩める
- **通知**: 翌取引日の 9:30 ごろに、約定した AI の売買（株数・価格・口座・確信度・候補に入った理由・損益・売った理由）と、前日の「🧠 AI の判断」を 1 通にまとめて送る。注文を出した時点では知らせない（自分が AI の注文を見て、翌朝に同じ銘柄を同じ値段〔始値〕で買えてしまわないようにするため）
- **🧠 慎重AIの判断**: 売買しなかった日も毎取引日に送る。銘柄ごとに、売り・買い・持ち続け・見送り・安全ルールで除外を分けて、Jev の確信度・基準・理由（基準に届かない、1 日の上限、現金不足、どの安全ルールに当たったか）と、判断に使った材料（RSI・25 日線からの乖離・MACD・5 日の値動き・提案からの値動き、保有なら含み損益と保有日数）を表示する。Jev は理由の文章を返さないので、「理由」はルール側の理由と判断の材料になる。判断の記録は DB の `ai_decisions` に残る

## 大胆 AI
急騰・出来高の急増・新しい材料をきっかけに、場中に素早く売買する AI。候補は慎重 AI と同じ（大胆 AI がすでに持っている銘柄は除く）。

- **始まり**: 大胆 AI を追加したときに、慎重 AI のその時点の状態（現金・入金額の合計・保有・売買履歴・総資産の記録）を複製して始めた（Bot の起動時に 1 回だけ）
- **判断のタイミング**: 取引日の 10:00・11:00・13:00・14:00・15:00。株価（約 20 分遅れ）を見て、その場の株価ですぐ約定する（自分の取引時間中の売買と同じ条件）
- **きっかけ**: 前日比 +3% 以上、今日の出来高が 20 日平均の 2 倍以上、提案から 1 営業日以内の新しいプラス材料、のどれかに当たった候補だけ Jev に聞く（場中に見る候補は 30 件まで）
- **買う**: Jev に「数日で上がるか（短期）」と「数か月以上持つ価値があるか（長期）」を 1 回で聞く
  - 長期の確信度が 60% 以上で短期以上なら、**NISA** で買う（今年の NISA 枠の残りが 15 万円以上あるとき）
  - 短期の確信度が 60% 以上で、税金・手数料を引いても見込みがプラスなら、**特定口座**で買う（NISA の枠を短期の売買で使わない）
  - 1 回 30 万円。確信度の高い順に買う
- **売る（短期・特定口座）**: その場の株価で、次のどれかに当たったら売る
  - 利益確定: +6%
  - 損切り: -4%
  - 含み益が出た後、保有中の最高値（終値）から -3%
  - 最長保有: 5 営業日
- **売る（長期・NISA）**: 場中は -15% の損切りだけ。大引け後に Jev の「売るべきか」で見直し、確信度 65% 以上なら翌取引日の始値で売る
- **売買しすぎの防止**:
  - 買いは 1 日 2 件まで、保有は 6 銘柄まで
  - 売った銘柄は 3 営業日は買い直さない
  - 同じ銘柄を Jev に聞くのは 1 日 1 回まで
  - Jev の呼び出しは 1 日 60 回まで（`bold_jev_daily_limit` で変更できる）
- **性格**: 固定（慎重 AI のように勝敗で変わらない）。戦術の違いを比べやすくするため
- **通知**:
  - 場中の売買は、判断の時刻ごとに、売買があった回だけ 1 通にまとめて送る（理由・短期か長期か・口座・きっかけ・確信度）
  - 大引け後の判断で出した売り注文が約定したら、翌朝の約定の通知と一緒に送る
  - 見送った候補も含めた 1 日分の判断（🧠 大胆AIの判断）は、翌取引日の 9:30 ごろに、慎重 AI の判断と並べて送る

## AI との勝負
- **チーム**: 🧑 あなた・🤖 慎重AI・⚡ 大胆AI の 3 チーム
- **勝敗**: 月ごとに、総資産の増減率（税金・手数料込み、その月の入金分を除く）で比べる。差が 0.05% 以内なら引き分け。あなたの成績は「あなた対慎重 AI」「あなた対大胆 AI」をそれぞれ数え、月ごとの順位（1 位のチーム）も表示する。株は毎週売買するものではないので、月単位で比べる
- **慎重 AI の性格**: あなたと慎重 AI の勝敗で変わる（大胆 AI との勝敗は関係しない）
- **記録**: 大引け後（16:00 の日足保存の直後）に、3 チームの総資産を毎日記録する
- **表示**: `/battle` と週間レポートの「🏆 AIと勝負」（今月の途中経過・通算成績・慎重 AI の性格・2 つの AI の今週の売買）
- **初期条件の設定（`/reset`）**: 現金（万円）と、すでに持っている銘柄を入力して、3 チームを同じ状態から始め直す。銘柄は 1 行に 1 銘柄、`証券コード 株数 平均取得単価 [取得日] [NISA/特定]`（例: `7832 100 3852 2026/05/19 NISA`。取得日の既定は今日、口座の既定は特定口座）。確認画面で「やり直す」を押すと確定する
  - **消えるもの**: 3 チームの保有・売買履歴・未約定の注文・毎日の総資産の記録（月ごとの勝敗）・AI の判断の記録
  - **保有**: 同じ銘柄を同じ取得単価・取得日で 3 チームに持たせる。含み益・含み損もそのまま引き継ぎ、売ったときの税金は取得単価から計算する。やり直した直後から AI の売買判断の対象になる（取引時間中の損切りと、その日の大引け後の判断〔損切り・最長保有・Jev の判断〕から）
  - **成績の基準**: 開始時の総資産（現金＋保有の直近の確定した終値での時価）を入金額の合計とし、通算成績・月ごとの勝敗はここからの増減で測る
  - **NISA 枠**: 今年 NISA で買った保有の取得額は、今年の枠を使ったものとして扱う。売った分なども含めて今年使った枠がもっと多いときは「今年すでに使った NISA 枠」に入れる
- **追加入金**: 必要なときに `/deposit` でいつでも入金できる。自分に入金すると、2 つの AI にも同じ額を同時に入金する（勝負の条件をそろえるため）。入金はレポート用チャンネルに知らせる。決まった時期の自動入金はない。NISA の年間枠（240 万円）は入金とは関係なく、毎年 1 月 1 日に戻る

## Web のポートフォリオ画面
Discord のコマンドとは別に、スマホで見やすい Web の画面で、仮想ポートフォリオと資産の推移を見られる。見るだけの画面で、売買などの操作はしない。

- **準備**: 環境変数 `DASHBOARD_URL` に、実行環境の URL（HTTPS）を設定する。見られる人は自分だけ（`DASHBOARD_USER_ID`、未設定なら Bot の所有者）
- **開き方**: Discord で `/dashboard` を実行し、自分にだけ表示されるボタンから開く。リンクは 5 分以内に 1 回だけ使える。開いた端末は 30 日間ログインしたままになるので、スマホのホーム画面に追加しておくとアプリのように開ける
- **ログアウト**: `/dashboard` の操作で「すべての端末からログアウトする」を選ぶ（スマホをなくしたときなど）
- **チーム**: あなた・慎重AI・大胆AI を切り替えられる
- **ポートフォリオ**: 総資産・入金額の合計からの損益・現金、国内株式の合計額と評価損益・前日比・前月比（率）、銘柄・口座区分ごとの比率の円グラフ、今年の NISA 枠の利用額、銘柄ごとの評価損益・前日比・前月比
  - 前日比は前の取引日の終値から、前月比は 1 か月前の終値からの変化。その後に買った銘柄は、取得額からの変化にする
- **推移**: 1か月・3か月・6か月・1年・全期間の、日ごとの総資産の積み上げ棒グラフ（銘柄ごと、または NISA／特定口座ごと。現金を含む）と、入金額の合計の線
  - 売買履歴と保存済みの日足から、日ごとの保有を計算し直して描く（記録を始める前の期間も出せる）
- **株価**: DB に保存済みの日足を使う（画面を開いても株価をダウンロードし直さない）。画面の右上に、いつの株価かを表示する
- **セキュリティ**: ログイン用のリンクとセッションは、DB にハッシュだけを保存する。Cookie は `HttpOnly`・`SameSite=Lax`（URL が HTTPS なら `Secure`）。ログインの失敗が 10 分に 20 回を超えたら、しばらく受け付けない。`/health` 以外のデータはログインしないと返さない

## 提案の答え合わせ
`/review` で、過去 60 日の提案が当たっていたかを確認できる。

- **基準**: 提案した時点で確定していた直近の終値（大引け 15:30 より前の提案なら前営業日の終値、後ならその日の終値）
- **評価**: 基準から 5 営業日後（約 1 週間）または 20 営業日後（約 1 か月）の騰落率と、同じ期間の TOPIX（連動 ETF 1306）との差
- **分類**: 承認・スキップ・未回答（未回答は比較から外して参考表示）、ニュースの銘柄と関連銘柄、Jev のインパクトの高低（1.5 以上かどうか）、材料の種類（記録を始めた後の提案だけ）
- **注目の提案**: ナイス承認（承認して上がった）・ナイススキップ（スキップして下がった）・惜しいスキップ（スキップしたのに上がった）
- 期間がまだたっていない提案は「評価待ち」として件数だけ表示する

## 関連銘柄の提案
ニュースの銘柄（A 社）が Jev の判定を通過すると、A 社と関係のある上場企業（B 社）についても、同じニュースが B 社の株価にとってプラスかを Jev で判定する。通過した B 社は「🔗 関連銘柄」として、A 社との関係（例:「B 社は A 社の主要販売先」）付きで提案する。

- **使う関係**: 主要販売先・主要仕入先、親会社・子会社、関連会社、合弁、資本業務提携、業務提携、技術提携、共同研究、取引先、製品導入
- **使わない関係**: 役員兼任・株式保有・取引金融機関（業績とのつながりが弱いため）
- **件数の上限**: 関連企業は 1 社あたり 3 社まで。業績への影響が大きい関係（主要販売先・仕入先、親子会社）を優先する。1 回の実行で判定する関連銘柄は 30 社まで
- **データの更新**: 関係データは DB にキャッシュし、7 日より古くなったら再取得する。件数が前回の 8 割を下回った場合は更新を見送る
- **出典**: [JP Market Vis](https://github.com/mattyamonaca/JP_Market_Vis) の `M5_company_relations.json`（有価証券報告書〔EDINET〕や企業の公式サイトから抽出された関係のうち、「確定」のもの）。自動抽出のため、誤りや古い情報を含むことがある

各メッセージの「JP Market Vis」ボタンを押すと、関係図のサイトが開く（銘柄のページを直接開く URL はないので、トップページが開く）。

## 権利付き最終日のお知らせ
- **データ**: 金融庁の EDINET コードリスト（API キー不要）の「決算日」。7 日ごとに取り直して DB にキャッシュする（件数が極端に少ないときは更新を見送る）
- **計算**: 権利確定日を期末（決算日）と中間（その 6 か月前）とし、権利付き最終日はその 2 営業日前（権利確定日が休みなら、その前の取引日から数える）
- **注意**: 配当・株主優待を実際に出すか、中間配当があるかは会社ごとに違う。お知らせは目安として扱い、会社の発表を確かめる

## 上場・上場廃止の同期
- JPX の上場銘柄一覧は DB にキャッシュし、7 日より古くなったら再取得する（JPX 側のファイル更新は月 1 回程度）
- 再取得したときに前回の一覧から消えていた銘柄は、上場廃止とみなす。監視中なら**自動で解除**し、シグナル用チャンネルに知らせる
- 新規上場銘柄は、一覧に載るまでニュースからの提案対象にならない。`/watch add`・`/buy` なら株価データで上場を確認して追加・購入できる（銘柄名は yfinance の英語表記になる）
- 取得した一覧の件数が前回の 8 割を下回った場合は、ファイル形式の変更などを疑って更新を見送る（全銘柄を誤って解除しないため）

## 注意
- yfinance は非公式の API で、レート制限にかかることがある。監視銘柄は十数件以内を推奨
- 日足は DB にキャッシュしている。初めて扱う銘柄だけ 5 年分をダウンロードし、以後は直近数日分だけを取得して更新する。株価は分割のみ補正し、配当では補正しない。6 年より古い日足は削除する
- 会社名の照合は、JPX の正式名称（と「ホールディングス」などを外した名前）で行っている。「トヨタ」のような略称だけの見出しは拾えない
- 本ソフトウェアの出力は投資助言ではない。投資判断は自己責任で行うこと
- 個人で使う前提。通知を他人に配信したり有料で提供したりすると、金融商品取引法の投資助言・代理業の登録が必要になる可能性がある
