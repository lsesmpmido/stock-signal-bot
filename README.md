# stock-signal-bot

ニュースから注目銘柄を見つけて Discord に提案し、承認した銘柄の売買シグナルを 2 種類のチャート画像付きで通知する Bot。

- **ニュース**: Google News RSS から記事を集め、JPX 上場銘柄一覧と照合して銘柄を特定する。そのうえで Jev (TypeSafe AI) でプラス材料かを判定する
- **シグナル**: 日足の RSI(14)・移動平均 25/75/200・MACD(12,26,9) を使う。状態が変わった瞬間だけ通知し、同じシグナルは 24 時間に 1 回まで
- **必要なもの**: Python 3.10 以上、PostgreSQL、Discord Bot、Jev の API キー

## セットアップ

### 環境変数

`.env.example` をコピーして `.env` を作り、値を書く。`.env` は Git の管理対象外。

```bash
cp .env.example .env
```

| 環境変数 | 内容 |
|---|---|
| `DISCORD_TOKEN` | Discord Bot のトークン（手順 1-2） |
| `DISCORD_CHANNEL_PROPOSAL` | 新銘柄提案を投稿するチャンネルの ID（手順 1-4） |
| `DISCORD_CHANNEL_SIGNAL` | 売買シグナルを投稿するチャンネルの ID（手順 1-4） |
| `DISCORD_GUILD_ID` | 任意。サーバー ID を入れると、スラッシュコマンドがすぐに反映される |
| `JEV_API_KEY` | Jev の API キー（手順 3） |
| `DATABASE_URL` | PostgreSQL の接続文字列（手順 2） |
| `JPMV_URL_TEMPLATE` | 任意。JP Market Vis の銘柄ページ URL。`{code}` が証券コードに置き換わる |
| `PORT` | 任意。ヘルスチェック用サーバーのポート（既定 8080）。実行環境が自動で設定する場合はそれに従う |

### 1. Discord Bot

**1-1. アプリケーションを作る**
1. [Discord Developer Portal](https://discord.com/developers/applications) を開き、Discord アカウントでログインする
2. **New Application** を押し、名前を入れて作成する

**1-2. Bot のトークンを取る**
1. 左メニューの **Bot** を開く
2. **Reset Token** を押し、表示されたトークンを `DISCORD_TOKEN` に書く
   - トークンは一度しか表示されない。なくしたら Reset し直す
   - トークンは Bot のパスワードと同じ扱い。人目に触れる場所に置かない
3. **Public Bot** を OFF にする（他人がこの Bot を自分のサーバーに入れられないようにするため）
4. **Privileged Gateway Intents** はすべて OFF のままでよい

**1-3. サーバーに招待する**
1. 左メニューの **OAuth2** → **OAuth2 URL Generator** を開く
2. SCOPES で `bot` と `applications.commands` にチェックを入れる
3. BOT PERMISSIONS で次にチェックを入れる
   - View Channels
   - Send Messages
   - Embed Links
   - Attach Files
   - Read Message History
4. 生成された URL をブラウザで開き、招待先のサーバーを選ぶ

**1-4. チャンネルを用意して ID を控える**
1. 提案用とシグナル用のテキストチャンネルを作る（例: `#新銘柄提案`、`#売買シグナル`）
   - 非公開チャンネルにする場合は、チャンネルの権限に Bot を追加する
2. Discord の **ユーザー設定 → 詳細設定 → 開発者モード** を ON にする
3. 次の ID をコピーして `.env` に書く
   - 各チャンネルを右クリック →「チャンネル ID をコピー」
   - サーバーアイコンを右クリック →「サーバー ID をコピー」

`/settings` と `/watch` は、「サーバーの管理」権限を持つメンバーにだけ表示される。

### 2. PostgreSQL

どの PostgreSQL でも使える（自前のサーバー、Docker、マネージドサービスなど）。空のデータベースを 1 つ用意し、接続文字列を `DATABASE_URL` に書く。

```
postgresql://user:password@host:5432/dbname
```

- テーブルは Bot の初回起動時に自動で作られる
- サーバーが SSL に対応していれば、SSL で接続する
- パスワードに `@` `:` `/` `#` `?` などの記号が含まれる場合は、URL エンコードする（例: `@` → `%40`）

Docker で手早く用意する例:
```bash
docker run -d --name stock-signal-db -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:16
# DATABASE_URL=postgresql://postgres:postgres@localhost:5432/postgres
```

### 3. Jev（TypeSafe AI）
1. [typesafe.ai](https://typesafe.ai/) でサインアップする
2. [console.typesafe.ai](https://console.typesafe.ai/) で API キーを発行し、`JEV_API_KEY` に書く

### 4. 起動する
```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

起動ログに次の 4 行が順に出れば成功:
```
ヘルスチェック用サーバーを起動しました (port 8080)
DB 初期化完了
JPX 銘柄一覧をダウンロードしてキャッシュしました (3712 件、上場廃止 0 件)
ログインしました: <Bot 名> (銘柄マスタ 3712 件)
```

Discord での動作確認:
1. `/watch add 7203` を実行し、「トヨタ自動車 (7203) を監視対象に追加しました」と出ることを確認する
2. `/watch list` で一覧に出ることを確認する
3. `/settings` でメニューが出ることを確認する

Jev の判定だけを試す:
```bash
.venv/bin/python jev_client.py "トヨタ自動車、通期業績予想を上方修正" "トヨタ自動車"
```

### 5. サーバーで常時動かす

常駐プロセスを動かせる環境ならどこでも動く。

- ビルド: `pip install -r requirements.txt`
- 起動: `python main.py`
- 環境変数: 上の表の値を実行環境に設定する
- メモリ: 512MB あれば足りる
- ヘルスチェック: `GET /health` が `ok` を返す（起動処理中は `starting`）。実行環境のヘルスチェック設定に使える

**同じトークンで Bot を 2 つ起動しないこと。** 手元とサーバーの両方で動かすと、通知が二重に届く。

### うまく動かないとき

| 症状 | 原因と対処 |
|---|---|
| スラッシュコマンドが出てこない | `DISCORD_GUILD_ID` を設定する。Discord を再読み込みする（`Ctrl+R`）。招待時に `applications.commands` にチェックを入れたか確認する |
| `/settings` や `/watch` だけ出ない | 「サーバーの管理」権限がない。サーバーのオーナーか管理者で試す |
| 起動時に DB 接続エラー | 接続文字列のホスト・ポート・パスワードを確認する。パスワードの記号が URL エンコードされているか確認する。実行環境から DB サーバーに接続できるか（ファイアウォールなど）確認する |
| 提案やシグナルが投稿されない（ログに `403 Forbidden` / `Missing Access`） | Bot がそのチャンネルを見られない。チャンネルの権限に Bot を追加する。チャンネル ID が正しいかも確認する |
| 通知が二重に来る | Bot が 2 つ動いている。片方を止める |
| しばらくすると Bot が反応しなくなる | プロセスが止まっている。実行環境のログを確認する |

## 使い方

| 操作 | 内容 |
|---|---|
| 提案メッセージの `➕ 監視対象に追加` / `❌ スキップ` | 提案された銘柄を監視対象にする / 見送る |
| `/watch add 7203` | 銘柄を監視対象に追加する（英数字コード `130A` も可）。JPX の一覧にまだ載っていない新規上場銘柄も、株価データで上場を確認できれば追加できる |
| `/watch remove 7203` | 監視を解除する（入力中に、監視中の銘柄が候補に出る） |
| `/watch list` | 監視中の銘柄を一覧表示する。メニューから選んで解除もできる |
| シグナル通知の `🗑️ 監視解除` | その銘柄の監視を解除する |
| `/settings` | 新銘柄提案（1日2回 / 1日1回 / OFF）と売買シグナル（15分 / 1時間 / 大引け後 / OFF）の頻度を変更する |

### 実行タイミング（日本時間）
- **新銘柄提案**: 1日2回なら 8:30 と 16:00、1日1回なら 8:30
- **売買シグナル**: 東証の取引日だけ動く（土日・祝日・12/31〜1/3 を除く）。データが約 20 分遅れるため、場中の時刻を後ろにずらしている
  - 15分間隔: 9:15〜11:45、12:45〜15:45
  - 1時間間隔: 10:00〜15:00 の毎正時と 15:45
  - 1日1回: 15:45

### 調整できる設定
DB の `user_settings` テーブルを直接編集する。
- `jev_positive_threshold`（既定 0.7）: プラス材料の確率がこれ以上なら提案する
- `jev_impact_threshold`（既定 1.0）: インパクト（0〜2）がこれ以上なら提案する

## 上場・上場廃止の同期
- JPX の上場銘柄一覧は DB にキャッシュし、7 日より古くなったら再取得する（JPX 側のファイル更新は月 1 回程度）
- 再取得したときに前回の一覧から消えていた銘柄は、上場廃止とみなす。監視中なら**自動で解除**し、シグナル用チャンネルに知らせる
- 新規上場銘柄は、一覧に載るまでニュースからの提案対象にならない。`/watch add` なら株価データで上場を確認して追加できる（銘柄名は yfinance の英語表記になる）
- 取得した一覧の件数が前回より 2 割以上減った場合は、ファイル形式の変更などを疑って更新を見送る（全銘柄を誤って解除しないため）

## 注意
- yfinance は非公式の API で、レート制限にかかることがある。監視銘柄は十数件以内を推奨
- 会社名の照合は、JPX の正式名称（と「ホールディングス」などを外した名前）で行っている。「トヨタ」のような略称だけの見出しは拾えない
- 本ソフトウェアの出力は投資助言ではない。投資判断は自己責任で行うこと
- 個人で使う前提。通知を他人に配信したり有料で提供したりすると、金融商品取引法の投資助言・代理業の登録が必要になる可能性がある
